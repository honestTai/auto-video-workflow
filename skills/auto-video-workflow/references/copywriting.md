# 口播文案与发布信息规范

先判断内容属于哪一类，再套结构，最后按「句子规则」逐句过一遍。
下面的例句只用来说明句式，写的时候换成自己的内容，不要原样照搬。

## 一、开头钩子（前 3–5 秒）

不寒暄、不自我介绍，第一句就给观众一个留下来的理由。四种公式任选其一：

| 公式 | 句式 | 适合 |
|---|---|---|
| 先亮结果 | 「你现在看到的，就是用 X 做出来的」+ 一个具体数字 | 教程、实测 |
| 反常识 | 「装得越多，反而越慢」「A，却 B？」 | 观点、避坑 |
| 硬数字 | 「三十六个工具，未聊先烧一万八千词」 | 数据解读、评测 |
| 戳误区 | 「很多人以为……，其实……」 | 科普、清单 |

钩子里的结果、数字必须是这条视频后面真的会讲、并且查得到出处的。

## 二、三种正文结构

### 清单型：「做某件事，这 N 个 X 你必须知道」

| 段落 | 时长 | 写法 |
|---|---|---|
| 钩子 | 0–5 秒 | 直接念标题，或戳一个常见误区 |
| 后果 + 承诺 | 5–12 秒 | 一句话说搞错的代价，一句话说这条视频给什么 |
| 条目 ×N | 每个 12–25 秒 | 报名字 → 一句话定位 → 适用场景 → 一个具体数字或可照抄的用法 |
| 速查回顾 | 8–15 秒 | 把条目压成「要 A → 用甲；要 B → 用乙」的对照 |
| 收尾 | 3–6 秒 | 一句把选择标准升一层的话 |

### 教程型：「我是怎么做到 X 的，把流程拆给你」

| 段落 | 时长 | 写法 |
|---|---|---|
| 结果钩子 | 0–6 秒 | 先亮结果，紧跟一个具体数字 |
| 路线预告 | 6–12 秒 | 「从……到……，再到……」，画面配章节条 |
| 步骤 ×3 | 每步 15–25 秒 | 每步先说做什么，再说为什么；顺序有讲究的要点明 |
| 踩坑 | 8–15 秒 | 一个真实踩过的坑和现在的解法 |
| 收尾 | 3–6 秒 | 一句总结 |

### 解读型：「这件事刚发生，它到底意味着什么」

| 段落 | 时长 | 写法 |
|---|---|---|
| 钩子 | 0–5 秒 | 事件 + 最反直觉的那个事实 |
| 发生了什么 | 5–20 秒 | 时间、主体、关键数字，全部来自一手信息 |
| 为什么重要 | 20–50 秒 | 2–3 个要点，每个要点一个证据（数据、实测、原话） |
| 另一面 | 50–65 秒 | 局限、争议或没解决的问题，避免一边倒 |
| 收尾 | 最后 5 秒 | 一句能带走的判断 |

## 三、句子规则

写完逐句检查：

1. **一个逗号一行字幕**，每行 6–16 个字。读起来要换气的句子就是太长了，拆开。
2. **口语，但不啰嗦**。用「你」「我」，不用「大家好」「那么接下来」「话不多说」。
3. **一句只讲一件事**。出现「并且」「同时」「以及」就拆成两句。
4. **数字和专名是锚点**。每 20 秒至少出现一个具体数字、工具名或可以照抄的指令。
5. **先结论后解释**。
6. **专有名词第一次出现时给一句白话解释**。
7. 英文词保持原样大小写（Codex、HTML、MP4）；配音念不准的词，在分镜里加 `tts` 字段写成想要的读法。
8. 每个分镜挑 1–2 个重点词用 `{花括号}` 包起来，字幕会自动高亮。

语速按每秒 5 个字估算（已含默认的 1.1 倍节奏）：

| 目标时长 | 字数 | 分镜数 |
|---|---|---|
| 60 秒 | 约 300 字 | 8–12 |
| 90 秒 | 约 450 字 | 12–16 |

一个分镜 = 一个画面 = 一两句完整的话（4–9 秒）。分镜太碎画面来不及看，太长画面会闷。

## 四、事实核对

- 年份、人名、版本号、价格、性能数字，逐条查到出处，记在 `script.md` 的「资料与出处」里。
- 查不到出处的说法不写；只有单一来源的说法，口播里带上来源（「官方博客说……」）。
- 画面上出现的数字必须和口播、出处一致。

## 五、发布信息

写进 `project.json` 的 `publish`：

```json
"publish": {
  "title": "别再给你的 AI 瞎装 MCP 了",
  "desc": "第一句：痛点或结论。\n① 要点一\n② 要点二\n③ 要点三\n最后一句：这条视频能带走什么。",
  "tags": ["AI", "MCP", "AI工具"],
  "cover": { "lead": "装得越多越慢的", "title": "MCP 避坑指南", "tag": "三条铁律" }
}
```

**标题**（`title`）

- **20 个字符以内**（抖音创作者中心的硬限制），最抓人的半句放最前面。
- 结构：一个让人意外的事实或结果 + 做了什么。
- 可用句式：「别再 X 了！……」「一句话 X？……」「用 X 做 Y，这 N 个 Z 必须知道」「X 实测：……」。

**可以吹，不能编。** 夸的是这件事本身有多省事、多意外；语气可以满，事实必须真：

- 能写：片子里真实发生的事、对观众的承诺（「看完就能照着做」）。
- 不能写：没有依据的战绩和数据（播放量、涨粉数、「全网首发」「99% 的人不知道」）。
- 不能写：片子里没讲的东西。

**简介**（`desc`）

- 第一句把痛点或结论说完：信息流里只显示开头。
- 中间 2–4 行要点，用 ①②③，是口播内容的提纲，不是复述。
- 最后一句：一个具体的收获。
- 不写「大家好」「感谢观看」，不堆表情符号。话题标签不用写进简介，发布时会自动追加。

**话题标签**（`tags`，3–5 个，不带 #）

- 1 个大类目（AI、AI工具、科技）
- 2–3 个具体的工具或方法名
- 不加和内容无关的热门话题

**封面三要素**（`cover`）

比标题更短、更狠，三处文字各管一件事，连起来要读得通：

| 位置 | 字段 | 字数 | 写什么 |
|---|---|---|---|
| 引导小字 | `lead` | 6–10 字 | 一个让人想点的事实 |
| 主标题 | `title` | 每行 ≤ 8 字，最多 2 行 | 这条视频讲的这件事 |
| 印章 | `tag` | 3–5 字 | 一个承诺或结论 |
